# 窥岛 PEEP ISLAND — T1 MVP（概念书 MVP 清单已闭合）

概念书 MVP 八项对照：时间同步✅ 3角色三层人格✅ 捏人+角色码✅（文字版捏脸码）
AI记忆对话+配额托底✅ 投喂循环（好恶/幸福度/每日一次）✅ 烦恼型主动消息✅
亲密度六阶段✅ 第四面墙全流程（手写台词+全屏演出+环境音）✅

微信式竖屏 UI 的 AI 生活模拟。React + Express + SQLite + Claude API。
对应《窥岛 T1 MVP 构建说明书》，已实现并验证的部分见下。

## 运行

```bash
# 1. 服务端（无任何 key 时自动进入脚本托底模式，可完整体验流程）
cd server && npm install
cp .env.example .env          # 填入你有的 key（Claude/DeepSeek/Kimi/Gemini 任一即可）
node --env-file=.env index.js # Node 20.6+ 原生读 .env，无需 dotenv
# 或临时：DEEPSEEK_API_KEY=sk-xxx node index.js   /   直接 node index.js（托底）

# 2. 前端
cd client && npm install && npm run dev
# 打开 http://localhost:5173  —— 默认暗色玻璃 UI，右上 ⚙️ 可热切换 AI 引擎
```

多引擎（成本 A/B）：Claude 原生、DeepSeek/Kimi 走 OpenAI 兼容、Gemini 单独。
运行时在 UI ⚙️「AI 引擎」面板里一键切换，用同一个角色比较哪个更像活人。

环境变量（全部见 `server/.env.example`）：
- `AI_PROVIDER` — 启动默认引擎 `claude|deepseek|kimi|gemini`，不填自动选第一个有 key 的
- `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY`(Kimi) / `GEMINI_API_KEY`
- `DAILY_QUOTA` — 每角色每日真实 AI 上限，默认 5（超出自动托底；测心跳时可调大）
- `CATCHUP_HOURS` — 离岛多久触发离岛报告，默认 4
- `*_MODEL` — 覆盖各家默认模型

## 已完成（2026-07-14 岛作主界面 · 朋友收集式信息架构）

抄的是**交互语法**不是美术资产（任天堂的立绘/图标不能用，上架会死）：

- **岛 = 主界面**（默认 tab）。手机壳保留 → 第四面墙不丢：你隔着屏幕俯视一座岛
- **小人头顶气泡**（朋友收集核心 affordance，优先级：烦恼❗/💭/💬 > 未读✉️ > 睡着💤 > 没喂🍽）
- **点小人 → 角色卡**（底部抽屉），不是直接进聊天：幸福/亲密双条、烦恼框、关系 chips、
  「TA眼中的你」画像、三动作（说话/投喂/窥梦，按状态自动禁用）
- **烦恼系统**（worry_text/level/at）：主动消息 1/3 概率带烦恼，岛上冒气泡，**你回一句 = 处理了**
  → 幸福+8 亲密+3 气泡消失 + 进记忆（实测 68→76 / 19→24）
- **HUD**：岛屿等级（均幸福/10）+ 时段 + 岛屿幸福度
- **幸福度衰减修正**：原每小时-1（离岛一周直接砸地板）→ 每12h-1、单次≤8、地板45。

## 已完成（2026-07-14 相遇小剧场 · 朋友收集核心循环）

看了《为什么捏完人之后觉得朋友收集不好玩》后的关键判断：
**任天堂的"双素材库+角色等级+微个性解锁"是没有 LLM 时代的工程妥协**——他们必须靠组合爆炸
堆事件数量，所以才有"20个一级小人一起无聊死"的陷阱。我们的事件是现生成的，
一级新人上岛第一天就有满级鲜活度。这套架构我们不需要。

但抄了三条：
1. **6-8人上限**（它为等级节奏，我们为 API 成本——殊途同归，写进设计约束）
2. **积累感要可见**：我们的"素材库"是记忆/羁绊/剧场/岛志 → 岛页底部常驻计数器
3. **"角色装傻，玩家吐槽"** → 相遇小剧场

**相遇小剧场（encounters 表）**：
- `findEncounterPair()` 找同地点的两个醒着的人（没有就让关系最好的两人"路上碰见"）
- `makeEncounter()` 一次 API 生成 3-5 拍：`旁白｜…` / `角色名｜台词`，关系 +2
- 离岛回来自动生成一场；也可点「👀 看看岛上」手动催
- 回放 UI 完全照搬朋友收集：岛变暗、两位主角走到台前放大、旁人灰掉、
  **底部字幕条逐拍播放**（旁白斜体灰、台词金色名字+白字）、说话的人发光跳动
- 实测输出：「圆子翻身压到小北的头发，小北惊醒。」→「嗷！你压到我了！！」→
  「唔……几点了，你饿不饿。」→「半夜两点你问我饿不饿！」→「被吵醒容易饿，我烤点红薯吧。」

## 已完成（2026-07-14 参数化渲染层 · 因为角色和岛都是玩家生成的）

**架构纠正**：之前把角色/岛当固定素材要「一张立绘 + 一张岛图」是错的——
角色是捏出来的、岛的建筑和材质会变，所以渲染层必须是**参数化组装**。

- **角色外貌参数** `look`（characters.look JSON）：
  肤色/发色/衣色自由取色 + 发型6 眼5 嘴5 衣4 + 身高 + 腮红
- **`Avatar.jsx` 参数化渲染器**：SVG 分层（衣→头→腮红→眼→嘴→发），
  岛上/角色卡/消息列表/剧场全部统一用它。**换美术时只替换每层的形状函数，look 结构不动**
- **捏人 UI 带实时预览**：发型/眼睛/嘴/衣服/腮红循环按钮 + 三个取色器 + 身高滑条 + 🎲 随机
- **捏脸码补全**：`PEEP1.` 码之前只带性格**不带外貌**（核心差异化的大洞），现已包含 look
- **岛屿场景数据化** `/api/scene`（GET/PUT）：
  `{ground, water, season, buildings:[{id,type,owner,loc,material,color}]}`
  - `Scene.jsx` 渲染：民居/商店/灯塔/码头四种形状 × wood/stone/brick 三种材质 × 自定义颜色
  - 地面材质 grass/sand/snow 可切（季节系统的接口已留好）
  - 建筑按 `loc` 定位，和角色日程共用同一套坐标——**改岛不用改代码，改 JSON 即可**

**给美术的交接点**（数据不变，只换渲染）：
1. `Avatar.jsx` 里每个 `<Hair/Eyes/Mouth/Outfit>` 的形状 → 换成你的 sprite/立绘图层
2. `Scene.jsx` 里每个 `<House/Shop/Lighthouse/Dock>` → 换成你的 3D 渲染图/模型
3. `LOCS` 坐标表 → 换成你的岛图上的实际锚点百分比
