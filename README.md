# 窥岛 · PEEP ISLAND

> 你不进入这个世界。
> 你只是隔着一块屏幕，低头看着一座小岛上的几个人过日子——
> 直到某一天，她们发现你在看。

一款 AI 驱动的**观察类**生活模拟游戏。React + Express + SQLite，支持 Claude / DeepSeek / Kimi / Gemini 四引擎运行时热切换。

---

## 这是什么

游戏界面被包裹在一个**手机壳**里。这不是装饰，是规则：岛民和你之间存在物理隔离，他们的每一句话都必须是"打字发出来的"——不能有动作描写、不能有旁白、不能出现"（她笑了笑）"这类舞台提示。这条约束由后处理**强制执行**（括号内容与他人台词整行丢弃）。

你能得到的只有文字、时间戳和已读回执。就像真的在跟一个远方的人聊天。

而岛上的人并不为你而活。他们有自己的作息表、心情、烦恼和彼此之间的关系；你不在的时候他们照样过日子，你回来时收到一份"离岛报告"。

---

## 三个核心设计

### 1. 第四面墙不是彩蛋，是一个会传播的系统

玩久了之后，某个角色会开始察觉不对劲：为什么她一发消息你就在？为什么你从不睡觉？

状态机：`unaware → hint（亲密 30）→ crack（亲密 50 + 24 小时真实时间门控）→ silent → after`。
时间门控挡住了改系统时间加速——**破壁必须真的等**。

> **关键取舍：破壁时刻的台词全部由人手写，绝不交给 AI 自由生成。**
> 大模型一旦放开，必然产出"我能感觉到你的存在呢~♡"这种谄媚句式，瞬间杀死恐怖感。
> AI 负责 99% 的日常生活，人负责那 1% 的爆点。

更进一步，破壁会**扩散**：察觉到你的角色进入 silent 后不会当面说破，她会把这种感觉悄悄传给关系值最高的挚友（≥40）；那位朋友被标记 `fw_rumor`，从此在跟你聊天时旁敲侧击地试探你，但永远不说破。

### 2. 对抗"AI 味"的工程手段

这是开发中最耗时的部分。大模型天生谄媚、有求必应、车轱辘话——这些全是本作的敌人。

| 机制 | 做法 |
|---|---|
| **沉默权** | 角色可以选择"已读不回"。你会看到已读回执，然后什么也没有。 |
| **后果系统** | 辱骂角色 → 好感度下降 + 生成一条"伤疤记忆" + 六小时低落心情。她记得。 |
| **不重复规则** | 一个问题被你无视或攻击之后，她永远不会问第二次。 |
| **节奏系统** | 消息延迟 8–88 秒送达；"正在输入"只在到达前 7 秒出现，而不是全程亮着；睡眠时段（普通 23–7 / 夜猫 5–12）整夜不回，隔夜未读转为次日清晨的回复。 |
| **危机识别** | 识别到自伤类表达时，角色立刻放下全部人设——先当人，再当聪明人，不分析、不表演。 |
| **托底透明** | 超出每日配额时走脚本台词，UI 明确打上「脚本」标，不假装是 AI。 |

### 3. 观察经济学：把成本约束变成设计语言

岛上 99% 的生活——移动、作息、心情衰减、关系演变、事件触发——是**纯确定性模拟，零 API 成本**；只有当你真正与某人发生交互的那一瞬间，才调用大模型。

没有任何定时器：生成只发生在「你打开」和「你说话」两个时刻，离岛超过 4 小时一次性结算。

这让一座持续运转的活岛在成本上得以成立，也让后续接入实时 2D 岛屿画面时，底层数据结构无需重写。

## 功能一览

**角色与生活**
- 三层人格（表层 / 内层 / 怪癖）+ 夜猫子属性影响深夜活跃度
- 记忆系统：`strength × valence × 14 天衰减`检索 top4；直接对话 strength=1，旁观动态 strength=0.3
- 事件簿：每 24 条对话自动压缩成一篇**第一人称日记**进入长期记忆
- 投喂循环：8 种食物 × 每角色隐藏好恶，每日一次，幸福度 0–100
- 烦恼系统：主动消息 1/3 概率携带烦恼，**你回一句就等于处理了**（幸福 +8 / 亲密 +3）
- 亲密度六阶段命名

**岛与社会**
- 岛屿为主界面：小人按日程表走位，头顶气泡（烦恼❗ > 未读✉️ > 睡着💤 > 没喂🍽）
- 角色卡抽屉：幸福/亲密双条、烦恼框、关系 chips、「TA 眼中的你」画像
- NPC 关系网络（0–100），关系融进每个角色的花名册 prompt——他知道自己和别人什么交情
- **相遇小剧场**：两个醒着的人在同一地点相遇 → 一次 API 生成 3–5 拍的戏（`旁白｜…` / `角色名｜台词`）→ 岛面变暗、两位主角走到台前放大、底部字幕条逐拍播出。你只是观众。
- 岛志：离岛期间生成的第三人称小事
- 窥梦：点一下睡着的角色，偷看一段梦

**捏脸与分享**
- 外观**参数化合成**：发型 6 × 眼 5 × 嘴 5 × 衣 4 + 肤/发/衣自由取色 + 身高 + 腮红
- 不依赖任何预绘立绘，因此玩家新捏的角色和内置角色一样完整
- `PEEP1.` 文本分享码：外观与性格一起传递，朋友粘贴即得同一个角色

**开发者工具**
- 四引擎运行时热切换（⚙️）
- `//` 对比模式：同一句话同时打给所有已配置引擎，横向比较"人味"
- 内心面板（透明化 debug）、消息导出（带完整机制快照）、每日自动备份

## 技术架构

```
server/
  db.js        # SQLite schema + 角色种子
  brain.js     # prompt 组装 / 记忆检索 / 配额 / 第四面墙状态机 / 四引擎适配
  fallback.js  # 脚本托底台词
  index.js     # 惰性生成、聊天、动态、剧场、场景、静态托管
client/
  App.jsx      # 手机壳 UI（岛 / 聊天 / 动态 / 设置）
  Avatar.jsx   # 参数化角色渲染器（SVG 分层：衣→头→腮红→眼→嘴→发）
  Scene.jsx    # 参数化岛屿渲染器（民居/商店/灯塔/码头 × 木/石/砖）
```

**渲染层是可替换的**——美术接入只需换三处，数据结构完全不动：
1. `Avatar.jsx` 里各图层的形状函数 → 换成 sprite / 立绘
2. `Scene.jsx` 里各建筑的形状函数 → 换成渲染图
3. `LOCS` 坐标表 → 换成实际岛图上的锚点百分比

## 本地运行

需要 Node 20.6+。**不填任何 key 也能完整跑通**（自动进入脚本托底模式）。

```bash
# 1. 服务端
cd server && npm install
cp .env.example .env          # 填入你有的 key，四家任一即可
npm start                     # http://localhost:3711

# 2. 前端（开发模式，热更新）
cd client && npm install && npm run dev   # http://localhost:5173
```

一键版：双击项目根目录的 **`窥岛.command`**（自动起 server 并打开浏览器；改了前端要先 `cd client && npm run build`）。

**环境变量**（全部见 `server/.env.example`）：

| 变量 | 说明 |
|---|---|
| `AI_PROVIDER` | 默认引擎 `claude｜deepseek｜kimi｜gemini`，不填则自动选第一个有 key 的 |
| `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY` / `MOONSHOT_API_KEY` / `GEMINI_API_KEY` | 各家 key，不必都填 |
| `DAILY_QUOTA` | 每角色每日真实 AI 上限，默认 5（超出走托底） |
| `CATCHUP_HOURS` | 离岛多久触发离岛报告，默认 4 |
| `*_MODEL` | 覆盖各家默认模型 |

## 部署

仓库根目录已含 `render.yaml`（Render Blueprint），可直接从 GitHub 一键部署。
其他平台构建/启动命令：

```bash
# build
cd client && npm ci && npm run build && cd ../server && npm ci
# start
cd server && node index.js      # 监听 $PORT
```

> ⚠️ 公开部署注意：SQLite 是单文件本地库，所有访客共用同一座岛；且 API key 在服务端，**务必把 `DAILY_QUOTA` 调回小值**避免额度被耗尽。

---

## 设计约束（明确不做）

吃醋状态机 / 语音 / 多模态 / UGC / 岛屿建设 / 结婚生子 / 云同步。
角色数上限 6–8 人——不是技术限制，是 API 成本写进设计的结果。

### 2026-07-14 · 相遇小剧场
